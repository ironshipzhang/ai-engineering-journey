# E2a 实施交接：远程编码接入验证

日期：2026-10-29。实现完成，待主会话复核；未提交或推送。

## 本轮解决了什么

E1 把原始资料变成有来源、可检查的片段。E2a 在这个基础上验证：这些片段能否通过用户选定的百炼服务变成结构合法、对应关系清楚的向量。

```text
E1 原文/目录 + prepared corpus
  → check：资料与构建是否仍匹配、产物是否完整？
  → embedding 配置与输入校验
  → 文档编码 10 + 5 → 问题编码 1
  → 响应顺序还原、向量校验、用量记录
  → 编码验证结果 JSON
```

这条路径独立于现有 Agent，不调用 DeepSeek。输出尚不能直接称作完整向量索引；查找相似片段、组织上下文、生成带来源回答以及 Agent 主动调用检索工具均未实施。

## 文件与运行

- `toy-agent/dashscope_embedding.py`：独立读取 embedding 配置，百炼原生同步 HTTP、响应/向量校验。
- `toy-agent/verify_embedding.py`：E1 检查、预算、分批调用、顺序映射、部分结果及安全错误保存。
- `toy-agent/test_embedding.py`：15 项离线行为测试，全部使用临时资料、假密钥和模拟响应。
- `config.example.toml`：保留用户新增 embedding 表，整理成无真实密钥的占位示例，补充 endpoint/dimension；未覆盖 local.toml。
- `test-output/e2a-20261029-001.json`：已忽略的本次真实验证记录。

在仓库根目录执行完整离线回归：

```bash
toy-agent/.venv/bin/python -m unittest discover -s toy-agent -p 'test_*.py'
```

以下命令会再次联网计费，供后续明确决定手动重跑时使用；**本轮验证已经执行，不需复核时再调用**。输出名必须未存在：

```bash
toy-agent/.venv/bin/python toy-agent/verify_embedding.py \
  --prepared test-output/e1-20261028/build-001 \
  --endpoint https://ws-kicad9ful35400g7.cn-beijing.maas.aliyuncs.com/api/v1/services/embeddings/text-embedding/text-embedding \
  --output test-output/e2a-manual-new.json
```

可通过 `--config` 指定其他本地 TOML。默认使用 config/local.toml，默认 1024 维；endpoint 命令参数覆盖配置值但不写回文件。用户确认华北 2（北京）业务空间地址后才发请求，没有轮流探测域名。

## 接口选择和官方依据

采用标准库 urllib 的单供应商原生 HTTP 客户端。只有一个同步 JSON 接口，不需要 SDK 的其他服务能力；批量、重试和错误记录由本项目显式控制。无新增依赖，pyproject.toml/uv.lock 未改，不下载任何本地模型。

2026-10-29 核实的官方资料：

- [通用文本向量同步接口](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)：text-embedding-v4 每批最多 10 条，每条最多 8192 tokens，默认 1024 维；支持 document/query、dimension、dense 输出及业务空间地址。
- [text-embedding-v4 模型与定价](https://help.aliyun.com/zh/model-studio/text-embedding-v4)：北京同步调用公开单价为 ¥0.5 / 百万输入 tokens。本轮不使用 BatchFile 价格。

请求采用 `input.texts` 和 `parameters`，返回读取 `output.embeddings`；不混用兼容接口或新版 SDK 的根级响应格式。实际 HTTP 返回的输入位置字段是 `text_index`，当前文档示例还可见 `index`；程序接受二者之一，拒绝同时出现、重复、缺失、越界或 bool 索引。保存字段名供复核。

文档和问题统一模型/维度，但分别传 text_type=document/query。没有本地模型检索前缀或 instruct。文本逐字使用 E1 chunk.text，不静默截断；本地每条 8192 UTF-8 字节保护上限**不是 8192 tokens 的精确计数**，可能拒绝服务本可接收的长文本；此处未引入 tokenizer，服务仍负责最终 token 限制。

唯一一次运行成功，预检通过后共发送 3 次请求，无重试、健康检查或额外模型调用。

| 1 | document | 10 | 1245 | 200 | 0.493 |
| 2 | document | 5 | 592 | 200 | 0.406 |
| 3 | query | 1 | 13 | 200 | 0.267 |

- 总计 1850 tokens，用量完整；整个验证约 1.172 秒（不含进程启动和工具调度）。
- 15 文档向量 + 1 问题向量，均为 1024 维，有限值、非零范数、完整唯一索引校验通过。范数范围约 0.9999999385–1.0000000925，程序未归一化；本次观察不能推广为服务永久保证。
- 问题：“数据库迁移失败后，重跑前需要检查什么？”这里只编码问题，没有检索或回答。
- E1 build_id：`d6fe4d2da557d44234c820edd504de94d7f9195c6cb02ca595e0d2f565415912`。

JSON 的 documents 每项保留 chunk_id、document_id、source_path、source、全局 input_row、请求批次与响应索引。向量可以追溯到 E1 对应片段，再通过来源行号及哈希核对原文。encoding 保存模型、维度、接口、文本类型、限长及归一化等实际配置；不保存密钥、请求头或原始错误正文。

## 已验证契约与限制

完整回归 **103 项通过**（原 88 + E2a 15）。离线验证覆盖：配置失败不联网、10+5+1 分批、乱序映射、非法索引和向量、维度不符、HTTP/超时停止、未知用量、坏响应仍保留已知用量、第二批失败保留第一批、E1 过期/损坏阻止读取配置及联网、输出拒绝覆盖和安全失败保存。真实失败未人为触发，不能把模拟测试说成供应商失败实测。

- 请求前独占预留输出文件；E1 check 后才读取认证配置并编码，失败不自动重建。
- 每次网络操作超时 30 秒，不是全流程硬时限。关闭重试和重定向，最多 3 次尝试，失败立即停止。资料超过 20 片段时显式选前 20 作为样本，仍预留一次问题请求；没有扩展请求预算。
- 已知 usage 先于向量校验提取；未知用量标记 complete=false，不能推断为零计费。无余额或月预算自动拦截。
- 输出只在运行结束写入；普通异常返回后保留成功批次，但强制终止、磁盘写入失败可能留下空/部分 JSON，没有事务保存或断点恢复。不能因文件存在就认为运行成功，要读 status。
- check 验证的是启动编码时的资料快照，没有跨网络过程锁住源文件，也没有建立完整向量索引生命周期。
- 当前配置支持范围有意较窄：明确的百炼业务空间原生 HTTPS 地址及 v4 支持维度。其他地址/API 类型需要另行确认，不能盲目修改后携带密钥探测。
