# 工程决策

## 2026-10-10：摘要结构由程序校验，缺字段不得补为空数组

- 约定：progress、blockers、next_steps 必填，值为字符串数组，可为空；元素必须是非空字符串。当前固定结构不接受额外字段。
- 原因：显式 [] 与未回答字段不同。自动补齐会掩盖模型遗漏，尤其可能把漏答阻塞项解释为没有阻塞项。
- 实现：请求使用 DeepSeek JSON 模式，Python 标准库解析后做本地校验；截断输出直接失败。
- 取舍：无需添加依赖，适合三个简单字段；结构复杂后再考虑 schema 校验库或模型端 schema 约束。
- 限制：JSON 语法和字段正确不保证事实正确，后者需要独立的内容评估。

## 2026-10-10：固定一次只读工具调用与两次模型请求

历史设计；请求组织方式已由下方有界 Loop 决策替代。工具与摘要的本地校验原则保留。

- 第一次请求声明 get_project(project_id: string)，指定 tool_choice 为 get_project，关闭思考；此阶段不启用摘要 JSON 模式。模型只接收查询意图和工具定义，不预先获得项目状态。
- 本地要求 finish_reason=tool_calls，恰好一个 function 调用，ID 非空，工具名为 get_project；arguments 必须是 JSON 字符串，仅包含非空字符串 project_id。随后显式调用 Python 函数，无动态函数查找或 eval。
- 仅支持虚构项目 xingqiao。非法调用或未知项目直接失败，不将错误送回模型修复，不重试。
- 第二次请求保留原对话，追加 assistant 工具调用与绑定相同 tool_call_id 的 tool 结果，不再提供 tools，启用现有摘要 JSON 模式与本地结构校验。
- 两次请求各保留 30 秒网络超时、400 输出 tokens 上限、用量与结束原因展示，均收到有效用量后显示合计。第二次请求失败时首次用量已展示；无响应的请求无法获知实际 token 用量。30 秒为每次网络操作超时，不是整个流程的总时限。
- 取舍：指定工具便于学习协议与执行边界，本次不验证模型自主选择工具的能力；固定流程没有通用 Agent Loop、MCP、RAG 或写操作。
- 官方接口参考：https://api-docs.deepseek.com/api/create-chat-completion/ （2026-10-10 查验）。

## 2026-10-10：模型自主选择工具，有界循环与任务内成功缓存

- 每轮仅提供 get_project，取消指定 tool_choice，使用 API 默认 auto。请求同时携带 response_format=json_object，提示词约束最终摘要；模型选择提出调用或 stop 回答，程序负责准入与退出。
- 官方 Chat Completions 文档列出 tools、JSON 输出模式和工具默认 auto，但未单独明确保证组合行为。2026-10-10 一次真实运行验证 deepseek-flash 非思考模式下，该组合能完成工具调用和 JSON 摘要；不外推到其他模型或所有异常路径。
- 每轮最多一个工具调用，最多 5 次模型请求，包括最终摘要请求；第五轮仍要求工具时不执行，避免没有额度回传结果。第五轮有效摘要可正常结束。
- 仅缓存同一任务内成功查询结果，以解析后的 project_id 为键；调用 ID 与参数 JSON 的格式不影响缓存键。缓存命中仍以当前调用 ID 回传结果，模型请求仍计数。
- 工具失败立即终止，无失败缓存或自动恢复；缓存不跨任务保存，避免引入失效策略与额外状态管理。
- 最终摘要必须已有成功项目查询结果且结构校验通过；直接回答不会触发程序补发查询或自动重试。非法调用、截断和超限均明确失败。
- 每轮先记录本轮和累计用量，再执行响应分支；失败不丢失已确认用量。不实现通用工具调度、MCP、RAG 或写操作。
- 官方来源：https://api-docs.deepseek.com/api/create-chat-completion/ （2026-10-10 查验）。

## 2026-10-10：事实评估先隔离摘要环节并逐条对照

- 用 6 条虚构状态及语义检查点建立基线，不使用唯一答案或关键词匹配充当事实判定。结构校验自动执行，事实与字段要求由逐条对照评审；本轮 Codex 初评待用户复核，不宣称自动事实评分。
- 评估脚本将完整状态直接提供模型并禁用工具，复用原摘要提示词与请求限制；隔离摘要能力，避免把工具选择失败混入内容评估。Loop 仍用原有工具流程，with_tools 默认 True。
- 原始状态、生成摘要、提示词与用量保存用于复核；评审标签不发送给模型。每条样例最多一次请求，失败记录后继续其他独立样例，不自动重试。
- 未提供阻塞信息时 [] 仍遵循当前提示词，但不得解释为确定无阻塞。本次只记录结构表达限制，不引入新字段或修复提示词。

## 2026-10-11：一次共享提示词实验，冻结规则并保留退步证据

- 用通用规则明确 next_steps 保留行动、计划、前提、时间和不确定性；blockers 保留阻塞与风险，排查进展附于对应阻塞。保持三字段结构及原有执行边界，不为修复内容问题引入程序特判。
- 原六条评审规则不变，新增两条在改词前固定；预算仅旧提示词新增 2 次、新提示词 8 次。旧输出可见，不声称新增样例是严格独立保留集。
- 仅修改一次提示词，看到新结果后不继续调词或增加调用。原六条改善但新增样例出现风险字段退步，保存候选与全部证据，接受或后续处理由主会话决定，不以总分掩盖退步。
- Evaluate 仅新增可选 --cases 参数，默认行为兼容原六条；真实评估仍隔离摘要环节，Loop 只由现有离线测试回归验证。

## 2026-10-11：按摘要下游用途拆分验收维度（V2）

- 已确定用途：人工阅读摘要；程序单读 blockers 筛选关注项目；人工可单读 next_steps 了解行动及计划。摘要暂不自动决定发布或执行操作。
- blockers 必须保留当前阻塞及明确风险，[] 仅表示本次未提取到，不能作为确定无风险的证据。next_steps 需自带计划前提、时间与不确定性，允许对应风险有依据地跨字段重复。
- 分别评估事实保留、字段归属和表达关联，不合成一个通过率：错字段会损害独立消费，但不等于事实在全摘要消失；单纯表达问题也不应与关键风险遗漏等量混合。
- 排查与原因状态须清楚关联阻塞，不强制同一数组元素；普通条件计划及单纯缺信息不自动当风险，有歧义标待讨论。
- V2 独立复核记录追加于 EVALUATION.md，保留旧标准、结论及原始规则和输出。标准调整不等于模型改善，不自动接受候选；本次不改提示词或调用模型，后续处理由主会话决定。
- 主会话补充：关联以完整摘要为评审上下文；存在唯一合理故障对象时允许上下文关联，不要求同项，不能借原文补足摘要中缺失的指向。多对象歧义另行标记。当前提示词保留为实验候选，尚未通过 V2 质量验收，不回退，继续冻结改词与模型调用。

## 2026-10-11：结束小样本提示词调优，推进 Agent 机制学习

- 用户已理解构造评估数据、批量采集、比较版本和内容评分的范式，当前缺少真实业务数据；继续围绕八条虚构样例改词的学习收益有限，因此结束此项练习，保留候选及质量限制，不宣称质量验收通过。
- 下一项实现结构化运行结果与执行轨迹，只做离线机制验证。模型调用冻结指本项不联网，不是永久禁止后续 RAG、MCP 或端到端验证所需调用。
- 完整路线恢复初始学习目标中的 Tool Registry、RAG 与 MCP；每项只实现最小机制。Skill 和流式输出可选，生产业务质量、权限、审批与部署进入后续工程项目。
