## 1. 已确认共识

### 最小场景与阶段分工

- 首阶段问答只依据虚构文档，不读取星桥等项目的当前状态，不进入现有 Agent Loop。
- E1 准备资料并收敛切块、来源和版本约定；实际向量构建属于 E2。
- E2 使用固定流程：程序根据用户问题检索相关片段，将问题、片段和来源一起发送给生成模型回答。检索完成不保证一定有相关结果。
- E3 再将检索包装成只读 tool，由模型判断是否调用以及使用什么 query，程序负责校验和执行。E3 的详细控制流程尚未设计。
- “先固定、后自主”指 E2 与 E3 两个实现阶段，不是同一次对话中首轮强制检索、后续轮次自主调用。

### 文档与展示

- 三份虚构短文档：《发布规范》《数据库迁移手册》《发布后检查清单》。中文为主，允许 SQL、rollback 等自然技术术语，每份约 600–1000 汉字。
- 每份文档只保留一个有效版本参与检索，但保留版本标识。允许后续修改并重建，不在初期同时检索历史版本。
- 回答简短，在相关结论旁标来源编号；下方列文档名称、版本、章节和原文短摘录，便于人工核对引用是否支持结论。机器输出 schema 尚未确定。
- 资料只作参考数据，不作为执行指令。证据不足时明确说明，不仅凭项目状态推导发布结论。

用户接受下面这对问题及展示方向。对应条款仍是待编写的虚构内容，并未创建知识库文件。

| 类型 | 问题 | 文档设计与预期行为 |
| --- | --- | --- |
| 有答案 | 数据库迁移失败后，重跑前需要检查什么？ | 手册明确要求检查执行日志、迁移版本记录和是否部分执行。回答保留这些要求并引用适用条款。 |
| 无答案 | 紧急发布能否跳过迁移验证，由谁批准？ | 资料规定常规发布需要验证，但不规定紧急豁免及审批人。可以说明已知常规要求，必须明确不足以确认豁免和审批人，建议向规范负责人确认。 |

无答案例子刻意包含相关内容：找到片段不等于找到足以回答问题的证据。回答应限定为“现有检索证据不足”，不能仅凭未检索到就断言全部文档不存在相关规定。这两个问题用于明确场景，不代表已形成完整评估集或验证了效果。

### 索引触发、检查与过期行为

- Toy 采用手动全量重建：用户通过程序的明确重建命令触发，不由模型选择调用重建 tool。具体命令名称未定。
- E3 只向模型提供文档检索能力；索引重建会写入数据，若使用 embedding API 还可能产生费用，因此不纳入当前只读 Agent 工具范围。
- 保存文档指纹和处理配置，用于比较当前资料与索引构建时的输入。每次问答开始、检索之前检查，而不是只在程序启动时检查。
- 检测过期后说明原因、提示手动重建，并拒绝本次正式问答；不使用旧索引继续生成，不自动重建，也不为过期提示调用生成模型。
- “过期”指输入资料或处理配置与索引不匹配，不是按时间自动到期。指纹一致仅说明输入匹配，不说明内容正确或检索有效。

## 2. 有理由推荐、但细节尚未确认的候选

- 指纹记录建议包含文档清单及各文档内容哈希，以识别新增、修改和删除。处理配置建议包含切块规则版本及参数、embedding 模型标识和编码配置。具体字段、哈希算法和配置比较方式待确定。
- 文件无法读取时应报告无法检查资料，不将其解释为资料未变化。错误分类及展示契约待确定。
- 先构建并校验新索引，再切换活动版本，避免半成品被查询；全量重建后的索引只纳入当前文档集合，使已删除文档退出新索引。这是前序讨论的建议，本轮尚未逐项确认实现行为。
- 若保留构建失败前的旧索引，其存在不意味着可以绕过已确认的过期拒绝策略；保存旧文件与允许旧版本正式问答是两个不同决定。

## 3. 尚待核实或决定

1. 构建期间文档再次变化如何处理，新索引如何校验和切换，构建失败保留哪些数据，以及删除文档的验证方式。无需提前扩展为通用后台更新框架。
2. 具体文档条款、适用范围，切块边界与大小、重叠策略，文档/片段标识、来源定位和版本字段。
3. embedding 的本地/API 候选：中文及混合技术文本适用性、query/document 编码、索引兼容、依赖与下载成本、API 价格、许可和 M1 Pro 支持。需查官方资料，不默认 DeepSeek 生成接口提供所需 embedding 能力。
4. 存储格式、关键词检索对照与向量检索的最小范围、top-k 等选择；不因流行引入向量数据库服务、混合检索或 reranker。
5. 回答/来源的机器契约、证据不足表达和检索失败分类，以及 E3 的参数范围、任务完成条件、轨迹与缓存版本关系。
6. 后续验证需区分检索找错、遗漏、上下文组织问题和生成错误，并核对引用是否真正支持回答。本轮未执行验证，不宣称质量通过。

## 4. 建议的最小 E1 范围与验收条件

以下为提交主会话审阅的建议，尚不是完整批准的验收任务书。E1 不实现 embedding、问答生成或 Agent 工具集成。

| 建议范围 | 建议验收条件 |
| --- | --- |
| 三份虚构资料及范围说明 | 语言、长度、有效版本符合本轮共识；有答案问题的依据明确；无答案问题缺少豁免及审批依据，不暗藏相反条款。 |
| 切块与来源约定 | 每个片段可追溯到文档、版本、章节及对应原文；关键条件不因切块丢失；相同输入和规则产生可复现结果。 |
| 资料与处理配置的版本约定 | 明确哪些输入变化需要重建，以及文档新增、修改、删除如何反映在构建记录中；实际 embedding 配置值留待 E2 选型。 |
| 生命周期行为说明 | 写清直接命令触发全量重建、问答前检查、过期拒绝且无生成调用；构建失败和版本切换的待定点先确认后纳入实现要求。 |

问答前拒绝过期索引等运行行为需要在 E2 接入问答时验证。E1 先定义契约及可离线验证的数据准备行为，不能据 E1 文档完成就宣称完整索引生命周期已经实现。

本轮确认了三份中文短文档、各一个有效版本、有/无答案示例及带原文摘录的来源展示。E2 独立执行固定检索后回答，E3 再接模型检索 tool。Toy 采用用户直接命令触发手动全量重建，保存资料指纹和处理配置，每次问答前检查，过期提示并拒绝正式问答，不自动重建或调用生成模型。构建失败与版本切换细节仍待确认；embedding、存储、检索算法和完整验收契约尚未选定或核实。请审阅本文后继续这些讨论，不据本轮记录自动启动实现，不重开旧摘要调优。
