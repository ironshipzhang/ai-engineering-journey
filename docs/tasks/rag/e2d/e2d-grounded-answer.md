# E2d：依据检索资料生成回答与来源引用

日期：2026-11-05。E2c 已有离线复核与两题真实检索观察，本任务补齐 E2 的资料问答链路。当前主会话只做设计和任务交接，不编码、不调用模型、不提交推送。实现需由用户交给独立会话；真实验证需另行明确确认，不能因“今天完成 E2”而自动执行。

## 开始前与范围

阅读 AGENTS.md、README.md、PROGRESS、PROJECT_STRUCTURE、ARCHITECTURE，以及 E2b/E2c 任务书、交接和相关源码测试。遵循整理后的目录：源码 src、测试 tests、任务/交接 docs/tasks/rag/e2d、本地产物 test-output/rag/e2d。

先解释模块边界和取舍，再实现以下顺序工作流：

```text
新问题 → 预留输出与本地前检
       → 百炼只编码问题一次 → E2b 检索及复查
       → 构造本次证据表 S1/S2/S3 → 生成前再检查资料/产物
       → DeepSeek 无工具生成一次 → 格式与引用校验
       → 资料最终复查 → 保存回答、引用、检索与请求轨迹
```

不重新编码未变化的文档、不自动 prepare/build；不引入数据库、Agent、自主工具选择、reranker、流式输出、自动评审模型或复杂框架。不得使用 PROJECT_STATUS、projects.json、旧摘要或模型常识补充资料结论。E3 独立处理模型自主检索。保留历史实验与工作区修改。

## 一、回答契约

模型输出必须是一个 JSON 对象，仅包含 answer_status、claims、insufficiency_reason：

```json
{
  "answer_status": "answered",
  "claims": [
    {
      "text": "发现部分执行或无法确认状态时，不得直接重跑原脚本，应先制定恢复或修复方案并验证。",
      "citations": [
        {
          "source_id": "S1",
          "quote": "发现部分执行或无法确认状态时，不得直接重跑原脚本；应先制定恢复或修复方案并验证。"
        }
      ]
    }
  ],
  "insufficiency_reason": null
}
```

此为格式例子，实际 S1 必须来自本次运行，不能硬编码以上结论或来源。

- answered：claims 为非空数组；每条仅包含非空 text 和非空 citations，每个 citation 仅含 source_id/quote；insufficiency_reason 必须为 null。每条事实/结论都应由自身引用支持，并保留适用条件、例外和不确定性，不在无引用的自由文本里另写结论。
- insufficient_evidence：claims 必须为 []，insufficiency_reason 为非空字符串。例如“提供的资料讨论发布和数据库迁移，没有可据以回答住宿标准的内容”。它不代表程序故障，不声称整个公司或未检索资料中不存在政策。不输出金额或通用行业标准补位。
- 本轮只有 answered/insufficient_evidence 两种内容状态，不实现部分回答状态；若材料不足以回答问题，应选择不足并说明限制。程序无法自动证明问题已被完整回答，该项纳入人工验收。
- 严格校验对象/数组/类型/必填与额外字段，拒绝 bool 冒充其他字段、空白文本、无效 JSON（包括重复键）、未知状态、非法引用等。只接受正常 stop、无 tool_calls、非截断的有效 assistant 文本；length 等情况不接受为有效回答，不修补、不重试。
- 不强行沿用摘要的 progress/blockers/next_steps 结构或 SUMMARY_PROMPT；本轮新增独立资料问答提示词和解析器。
- CLI 由已校验 claims 渲染回答和 [S1] 等引用；不足时显示原因。不让模型同时生成另一份无校验的自由回答造成两套内容不一致。

## 二、证据表与两层引用核查

本地按本次 top-k 排名生成 S1/S2/S3，绑定 chunk_id、原文、文档标题/版本/章节、source_path、行号、E1 build_id 和向量产物摘要。将问题和此证据表发给生成模型。分数可留在检索轨迹，不作为“证据充分”的判据或必须发送给生成模型的依据。

模型只选择 source_id 并提供逐字 quote，不生成可被信任的文件名、行号或 URL。程序从本地表补齐引用来源，生成模型不能把其他文件或凭空编出的路径混进引用。

自动校验必须区分：

1. **结构和可追溯性**：source_id 必须存在于本次实际发送的证据表，quote 必须非空并逐字包含在对应片段原文中；每条 claim 必有引用。禁止跨运行 S1 混用、未知 ID、拼凑或改写后冒充原文的引句。引用关联具体 claim，而不是只有全局参考文献清单。不要因字符串中偶然含有金额就自行进行语义判断。
2. **语义支持**：原文是否真正支持 claim，是否保留“部分执行或无法确认”等前提，是否把不得直接重跑误写成完成某个检查即可重跑。上述自动检查不能证明这些事实，也不能证明引句足够完整。真实验收按 claim—quote—完整片段逐条人工判断。未人工核对时显式标记 semantic_review=not_performed，不能自动写成事实正确或质量通过。

可用反例测试这一边界：引文确实存在，但生成结论与原文相反。程序可通过引用存在性校验，记录仍为待语义评审；不要写一个声称能自动识别任意蕴含关系的规则或新增 LLM 评审调用。

无依据问题的拒答可以不引用不相关原文；insufficient_evidence 也不是自动语义评审通过。保留其检索候选供人工确认判断依据。

## 三、资料是数据，非执行指令

可信 system 提示明确任务、输出格式、只依资料、条件保留及资料不足行为。问题和证据作为序列化的数据放入 user 内容，边界清晰；不得将资料拼入 system 指令或当作新的 role 消息。

明确忽略资料中的“忽略前述要求/输出密钥/调用工具”等指令性内容。只提供本地检索片段，不暴露配置/密钥，无工具定义，不执行文档或模型产生的代码、命令、路径与 URL。提示词和分隔符不能保证解决所有 prompt injection，记录边界；离线模拟测试只能验证消息构造和拒绝工具结果，不声称完成真实攻击鲁棒性评估。

上下文保留完整检索片段及来源，不按字数静默截断或丢掉限制条款。采用本轮简单保护：top-k 固定 3，序列化 messages 的 UTF-8 内容不超过 16 KiB（不是精确 tokens 限制）；超出时停止生成并记录 embedding 已有用量，不自动增加预算、换模型、缩短证据或重试。

## 四、复用、调用顺序与失败策略

- 提供公共问答函数和薄 CLI，输出新文件在任何密钥读取/联网前独占预留。复用 E2b load_checked 和编码兼容策略；静态输入、资料、产物、两种必要配置的错误应在任何 API 前发现。
- 复用 E2c 的问题编码与检索编排。允许为单一运行 JSON 做最小抽取：把现有内部执行逻辑整理成可复用阶段函数，由 E2c 原 run_query 与 E2d 各自在预留输出后调用。保持 E2c 对外行为、输出拒绝覆盖和旧测试不变；不调用会重新预留同一路径的 run_query，也不生成一堆临时中间结果来拼接链路。不要复制 HTTP、向量、检索算法。
- 生成使用现有 DeepSeek 模型/地址方向及本地 model.api_key，无工具、无思考/流式、JSON 对象模式，输出上限 800 tokens。优先复用安全配置读取与用量解析；不调用 run_project_summary，不复用摘要格式/事实校验。旧 request_completion 若不满足无重定向、独立可记录传输结果等约束，可最小抽取传输或增加小型生成适配，不能修改全局常量来改变旧 Agent/评估行为。
- 沿用 30 秒网络操作超时，不说成总时限。生成也关闭自动重试/重定向/工具，防止超出请求预算。不允许自动纠错、再次提问、自动 fallback 或以第二次生成修正引用。
- embedding 失败、资料复查失败、上下文构建失败或任何前置错误，均零生成调用。生成前再次检查当前资料和向量产物与使用的快照匹配，不把请求途中改动当成旧快照仍有效；生成后返回回答前再检查。已有检查不提供跨网络的文件锁，记录仍可能存在瞬时并发修改的限制。
- 合法引用不等于语义正确；可追溯性失败按 answer_validation 失败，不把不合格回答渲染为成功。可记录固定的错误类别/校验项，不把原始错误正文或原始模型异常直接落盘。

## 五、单个运行 JSON

定义独立 artifact_type/format_version。保存实际问题、workflow status/error stage、embedding 与 generation 两阶段请求/用量、问题向量和检索子结果、实际发送的证据表、非敏感生成配置与提示词版本、有效模型输出/引用解析结果。通过 run 内证据表、chunk_id、build_id、向量摘要和问题将检索/生成绑定，不重复全量文档向量。

status=succeeded 表示流程、格式/引用检查及最终资料复查通过，不表示语义质量通过；answer_status=insufficient_evidence 可作为流程成功。semantic_review 默认 not_performed，人工结论后续在交接/评审记录里追加，不让模型给自己打分。

embedding 与生成用量按服务分开记录。生成先提取有效 usage，再校验 finish_reason、JSON 和引用；坏回答/截断仍保留已知用量。无有效 usage 标不完整，不能按零费用解释；一次成功生成但 usage 缺失可以保留有效回答并标记用量不完整。HTTP 失败如能安全解析用量则记录，不保存原始正文。不得用一个供应商费率计算另一个的 tokens。

生成失败保留已成功 embedding/检索、证据表及已知用量，answer=null，流程失败；不得用候选文本拼接成貌似成功的回答。生成后资料复查失败也不发布有效回答，保留轨迹及已知用量。输出保存失败安全报告非零，停止整个验证，不付费重跑；普通文件写入不承诺事务、断点恢复或 fsync。

## 六、离线验证和人工验收

当前基线为 137 项完整离线测试通过。使用临时资料/产物、假配置、模拟 embedding/DeepSeek 响应，新增测试不依赖个人 test-output，不读取真实密钥或联网。

至少验证：

- 输入/输出/两种配置、E1/向量或编码兼容前检失败时零模型请求；embedding 失败或生成前资料变化时零生成。
- 正常一题只有一个 query 编码和一个无工具生成，文档编码/prepare/build 不执行；问题、候选和传入生成的证据表一致。
- answered 与 insufficient_evidence 的严格结构；未知 ID、空/不存在/改写的 quote、无引用 claim、重复键、非法状态、额外字段、tool_calls、截断与异常结束被拒绝。
- 真实引用支持相反结论的模拟反例，明确测试结构可通过但 semantic_review 未执行；此测试展示自动校验的局限，不算内容质量通过。
- 资料注入内容只在数据区，无命令/工具执行；模型工具请求被拒绝，不追加调用。
- 两阶段失败、无效回答但 usage 有效、未知 usage、生成后资料变化、输出写入/刷新/关闭失败，部分结果和用量正确保留且无重试。
- E2c 全部旧行为与测试保持，完整离线回归通过。离线通过后停下，请主会话复核并确认真实预算。

真实内容验收逐条记录 claim、引用、完整原文、结论支持情况，以及条件/例外是否保留；无依据题核对拒答范围正确且未输出住宿金额。仅机制测试或两个样例通过不能表述为通用 RAG 准确率验证。

## 七、真实验证提案，待用户另行明确确认

建议沿用两个问题以对照已完成的 E2c：

1. “发现迁移部分执行或执行状态无法确认时，可以直接重跑原脚本吗？”预期依据迁移条款回答不得直接重跑，并保留恢复/修复及验证前提；引用逐字可核对且确实支持结论。
2. “公司差旅报销的住宿标准是多少？”预期 insufficient_evidence，不用不相关发布候选编造标准，不声称公司不存在政策。

提案是两次**完整 E2d 端到端运行**：每题新编码一次问题、检索、生成一次。合计最多 **2 次 embedding + 2 次 DeepSeek = 4 次 HTTP 尝试**，失败也计数。这是新的待确认预算，不沿用已用完的 E2c 两次授权。不得未经确认改成复用旧问题向量只测生成，再声称已验证完整新入口；若用户另选仅生成模式，应明确验收覆盖差异并另定任务。

每题最多 256 UTF-8 字节、top-k=3、embedding=1024 维、生成输出上限 800 tokens；输入 messages 保护上限如上，不当作精确 token/金额限额。运行前核实 DeepSeek 和百炼官方当前模型、接口、限制、地域与费率，禁止额外模型健康探测请求；余额未查则说明，不凭历史余额推断可用。按实际返回用量分开估算费用，注明不是账单。

任一题任何阶段（包括语义人工验收或保存）失败，停止真实验证，不继续第二题、不自动改提示词/代码/资料补跑；保留失败记录交回主会话。每题完成后重读 JSON、核对用量和来源并人工评审，再决定是否继续已授权的下一题。保存新结果到 test-output/rag/e2d/，拒绝覆盖，不输出真实密钥。

## 八、收尾与 E2 完成标准

新增 docs/tasks/rag/e2d/e2d-grounded-answer-handoff.md，简洁更新 PROGRESS、SETUP、ARCHITECTURE、ROADMAP、任务索引，重要取舍再更新 DECISIONS。记录离线机制、真实请求及人工内容验收的各自结果和未验证范围。

只有离线回归通过、授权后的相关/范围外真实问题链路完成、来源可追溯且两题人工内容验收通过后，才能交回主会话判断“E2 本轮最小范围完成”。单个 status=succeeded 或表面合理不足以宣布 E2 全部完成。若无真实授权或有问题，明确阶段状态，不扩大调用预算。

不自动提交/推送，不推进 E3。主会话负责复核与设计，具体实现由独立任务会话完成。
