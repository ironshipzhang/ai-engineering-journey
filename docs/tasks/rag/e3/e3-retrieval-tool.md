## 一、最小行为与流程

```text
问题 → 独占预留输出 → 本地前检
     → DeepSeek 第一次请求：提供 search_knowledge 工具，模型选择是否调用
     → 调用校验与 Registry 分发 → 只编码当前问题 → E2b 检索 → 本次证据表
     → assistant tool_calls 消息 + 对应 tool 消息
     → 资料/产物复查 → DeepSeek 第二次请求：依据工具结果回答
     → E2d 回答/引用校验 → 最终资料复查 → 保存轨迹与回答
```

这是一次有界的 Agent 工具往返；不为演示而扩展到多工具、多轮检索、查询改写、缓存平台或通用 Agent 框架。本次独立资料问答入口不混入 get_project/list_project_issues，不修改旧项目摘要任务的提示词、完成条件或注册表。

第一次请求使用模型自主工具选择，不强制 tool_choice=required，不在请求模型前自动执行检索。第二次请求不再提供工具，要求最终回答；如果仍返回工具调用则拒绝，不执行或追加请求。两次请求上限是预算，不代表模型失败后可补发一次。

本入口只接受资料问答。本轮不增加闲聊模式：若第一次模型没有提出合法检索调用，记录 completion_gate / retrieval_not_requested 等明确的安全失败，answer=null，embedding 尝试为 0，不继续请求。不能将未检索说成“知识库没有答案”，不能接受无证据的 answered。模型提出请求与程序执行工具是不同动作，必须分开记录。

## 二、单工具与显式 Registry

只注册 search_knowledge，一个参数 query（字符串），不允许额外字段。top-k 固定 3，资料/产物/配置路径来自本次可信运行参数，不交给模型指定。

- 描述清楚：检索发布/数据库迁移等当前虚构资料，只返回候选原文与来源，不能保证问题有答案。不要在描述中塞固定答案或按问题硬编码工具选择。
- query 必须逐字等于用户本次实际问题，校验非空、可编码及既有限长；本轮不允许模型改写查询。未来改写会涉及新的证据绑定/预算，另行讨论。
- 复用既有显式 Registry 结构/注册项概念，将 schema、参数校验和本地执行关联。不使用 getattr/eval 任意分发，也不要为复用旧 SUMMARY_PROMPT 和项目约束而硬套旧摘要 Loop。
- 首次 tool_calls 必须恰好一个 function 调用；校验 finish_reason=tool_calls、无截断、合法且非空 ID、工具名、严格 JSON 参数（含重复键拒绝）、类型和 query 绑定。未知工具、多个调用或非法参数在执行前拒绝，零 embedding。
- 不因提出调用时同时带了自然语言就把它当作最终答案。把合法 assistant tool_calls 消息追加一次，再添加 role=tool、tool_call_id 为当前 ID 的结果；不得伪造 ID 或仅把工具结果塞到 system 中。
- 工具复用 execute_retrieval/E2b；不得在工具内部调用 run_answer 或生成接口，否则会产生隐藏模型请求。允许必要的小范围抽取，不复制向量/余弦/来源检查逻辑。一个成功工具结果返回本次证据 S1/S2/S3 和候选状态，不返回全量文档向量或密钥。
- 工具检索或复查失败就停止整个流程，保留轨迹，不通过把错误交给模型让其“自己修复”来追加调用。本轮最多执行一次工具，无缓存需求，不重试。

## 三、前检、资料边界与回答验收

输出独占预留在任何配置读取或请求之前。第一次 DeepSeek 请求前，就检查输入、E1/E2b 完整性、全量来源与当前资料、两种必需配置（包括 E2d 已修复的生成密钥字符校验）及编码契约。失败两供应商均零调用；不能先花一次路由请求才发现本地配置或资料错误。

为保持每次运行的绑定关系，记录初始 build_id 和文档向量摘要。实际执行检索工具时再次核对资料与磁盘产物仍匹配前检快照；检索后、第二次生成前与返回答案前继续复用磁盘检查。变化/损坏时停止，不自动重建、换库或使用旧数据。

第一次 system 描述工具协议与资料问答边界，问题是 user 数据；工具返回的原文同样是参考数据，不接受其中的指令。不得提供命令执行能力、读取其他文件或执行模型生成代码。控制 messages 序列化 UTF-8 不超过既有 16 KiB，超出停止，不截短关键条款。

第二次生成复用 E2d 的独立问答提示词/输出契约：answered 的每条 claim 绑定本次 source_id 与逐字 quote，或 insufficient_evidence 且 claims=[]。工具结果的 evidence_status=candidates_only，不能因工具成功/分数高就强制模型回答。

适当复用 grounded_answer.validate_answer 与本地引用解析，保持正常 stop、无工具、重复键/额外字段/类型/引文检查。来源必须来自本次实际工具结果；不能使用 E2d 旧运行的 S1 或旧证据填空。程序只校验存在性，可追溯不等于语义支持；semantic_review 仍为 not_performed，真实样例另行逐条审阅。

## 四、请求预算和传输

每次运行最多 **2 次 DeepSeek + 1 次百炼 query = 3 次 HTTP 尝试**，包括失败。工具验证失败可能只有 1 次 DeepSeek，检索失败可能只有 1+1；不要求花完预算。没有自动重试、重定向、fallback、修词重发或重新编码文档。仍为非思考、非流式、每次网络操作 30 秒、每次 DeepSeek 最多 800 输出 tokens。

优先在现有受控 DeepSeek 适配上最小增加“首轮 tools”参数能力；默认无工具行为保持 E2d 不变，不修改全局常量或旧 Agent 配置。首轮提供本次 Registry 的 schema，不意外带入其他工具；次轮明确无工具，使用 JSON 对象输出。接口参数组合开工时依据现有实现与官方文档核实；核实文档不能发模型探测请求。

不要复用默认会注入项目工具或可能跟随重定向的旧 transport 路径来绕过预算。若最小抽取传输，应对 E2d/E2c 回归，说明行为保持依据。没有新依赖需求，不引入 MCP；后续 MCP 是不同阶段。

## 五、单个运行记录

定义独立 artifact_type/format_version，保存 question、status/error stage、初始资料/向量指纹、实际非敏感配置、每轮 DeepSeek 请求数/finish_reason/有效用量、模型调用提议/校验结果、实际工具执行、当前 call_id、检索子结果与问题向量、本次 evidence、最终 answer/resolved_citations。不要保存完整文档向量副本或认证信息。

DeepSeek 两轮用量分别记并按服务汇总，embedding 独立记，未知用量标 complete=false；先提取有效 usage，再校验工具/回答。工具调用或引用无效仍保留已知用量，不能按零计费解释。工具失败或最后检查失败时 answer=null，保留成功前序步骤。输出保存失败非零且不自动重跑；普通 JSON 保存不承诺事务/锁/断点恢复。

trace 要能解释：模型是否提出检索、提议是否获准、是否真的发生 embedding/检索、哪一条 tool 结果被后续回答使用，以及为何结束。不将“模型选择正确”“候选足够”“回答受支持”混为一个成功指标。

## 六、离线验证先行

基线 168 项。使用临时资料/产物、假密钥、模拟两轮模型与 embedding 响应，禁止真实网络，不依赖个人 test-output。覆盖当前实际行为，不镜像实现细节。

- 正常单工具消息往返、call_id 绑定、只在模型请求后编码、两次无隐藏生成，最终证据与工具返回一致。
- 首轮不检索时有迹失败、不接受资料结论、零 embedding，不伪称知识库无答案。
- 未注册工具、两个调用、无效/缺失 ID、参数重复键/多字段/错误类型/query 不一致、截断或 finish_reason 不一致：零工具执行、零 embedding。
- 两配置/资料/产物前检失败时两服务零请求；模型请求期间或工具/生成期间原文、有效磁盘向量产物发生变化时按快照检查停止。
- 最后一次请求仍要求工具时不执行、不追加；超时/HTTP 错误/无效响应/未知 usage 和部分轨迹正确保留。
- 回答结构、引用存在性与资料不足继承 E2d；保留引用存在但结论相反的边界认识，语义审阅状态不自动通过。
- 覆盖拒绝与保存失败；确认原 E2c/E2d、旧 Agent 测试均通过。

## 七、真实验证提案（未授权）

离线完成后先交主会话复核。若后续用户明确确认，建议沿用迁移重跑题与差旅住宿标准题，各完整运行一次，用以比较 E2 固定工作流与 E3 模型工具选择。

两题合计上限 **4 次 DeepSeek + 2 次 embedding = 6 次 HTTP 尝试**，不沿用过去已用完的授权。每题 ≤256 UTF-8 字节、1024 维、top-k=3、每次 DeepSeek 输出 ≤800 tokens。任一步失败（含模型未检索、保存或语义审阅不通过）停止，不继续下一题、不补跑。第一题逐条核对通过后才执行第二题。

分别评审：模型是否提出正确工具、工具执行与来源是否正确、相关题的引用是否支持限制条件、范围外题是否明确本次资料不足。不得因为模型自主调用成功就宣称内容准确率提升。

真实调用前核实官方模型/接口/地域/费率，按服务实际 tokens 分开估算费用，不是账单；不发额外探测、不查询余额。以上仅提案，当前实现会话不读取真实密钥、不调用 API。
