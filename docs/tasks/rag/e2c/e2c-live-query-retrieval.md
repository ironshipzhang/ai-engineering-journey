# E2c：新问题编码与独立检索

日期：2026-11-04。当前仅准备任务书，未授权本轮主会话编码或联网。独立实现会话接到用户开工指令后先完成离线实现；下述真实验证方案必须另获用户明确确认才能执行。

## 阅读与目标

先阅读 AGENTS.md、README.md、docs/PROGRESS.md、docs/ARCHITECTURE.md、E2a/E2b 任务书与交接，以及 dashscope_embedding.py、json_retrieval.py、verify_embedding.py 和相关测试。保留已有修改。

先解释最小设计和重要取舍，再实现：

```text
新问题 + 已有 JSON 文档向量
  → 输入/输出位置预检
  → E1 与向量产物完整性、来源及过期检查
  → 读取 embedding 配置，检查编码契约完全兼容
  → 单次百炼 query 编码
  → 响应校验
  → E2b search
  → 候选原文、分数、来源和运行记录
```

文档与编码配置不变时直接复用已有文档向量。此次不构建或重新编码文档，不自动 prepare/build，不改资料。Toy 仅用 JSON；不接 DeepSeek、生成回答、Agent 工具、E3、数据库、reranker 或新框架。后续“原文 + 问题 → 回答与引用”单独立项。

## 一、入口和前置检查

- 提供可调用函数和薄 CLI；输入新问题、prepared corpus、E2b 产物、top-k、本地配置路径、必要的显式 endpoint 及必填新输出路径。参数风格与已有程序一致，不扩展成通用服务。
- 问题必须是非空字符串，拒绝不能编码的字符及超过既有长度保护的文本，不静默截断。top-k 为正整数。问题编码输入与保存/展示的文本必须一致；如去首尾空白，应明示并一致使用，不暗中加前缀。
- 输出文件在任何密钥读取和联网之前独占预留。输出已存在、父目录无效或不能创建时停止，零 API 调用，不覆盖旧结果。预留失败无法写结果时输出安全诊断并返回非零。
- 调用 E2b load_checked/check_artifact，验证摘要、向量、全量原文/来源、当前 E1 资料及 build_id。失败零 API 调用；不自动重建或继续用旧数据。
- 复用 read_embedding_config，只使用 embedding 表及用户确认的 endpoint；不读取 [model] 的值用于生成，不显示密钥，不修改 local.toml 或无关配置。配置与密钥只在运行认证所需路径读取，不在工具中打印配置全文。
- 使用 E2b encoding_contract 比较实际将发送的 query 配置和文档产物契约，保留 endpoint 完全一致的保守策略。必须在请求前完成比较，不能请求后才发现模型/维度/文本类型等不兼容。沿用默认路径及 --config、--endpoint 语义，不猜测或轮流探测地域。

## 二、单次编码与复用检索

- 仅复用百炼原生客户端 request_embeddings，texts 中只有当前问题，text_type=query，模型/维度取已验证配置。每次运行最多 1 次 HTTP 尝试，失败也计入预算，无重试、重定向、健康检查或自动 fallback；沿用 30 秒网络操作超时，不说成流程总时限。
- 复用既有响应解析、索引/数量、维度/有限值/非零范数校验。不能因为 HTTP 200 就认为编码成功。
- 有效 usage 在向量校验之前提取；HTTP 失败但有有效用量时仍记录。未知用量 complete=false，不按零费用解释。仅保留安全错误、合法请求 ID 和必要状态，不保存认证头或原始错误正文。
- 成功编码后构造真实问题文本/向量/契约，调用 E2b search 返回 top-k。不要复制余弦算法，或直接调用 rank_vectors 绕过 E2b 的检查。search 再次检查 E1；若请求期间资料变动，停止并记录已发生请求及已知用量，不返回旧资料候选、不自动重试。
- 不修改文档向量产物。候选仅为 candidates_only，不设“有答案”阈值，不把余弦当正确率；无关问题也可能有 top-k，不能据此声称可回答。

## 三、结果与失败语义

输出为一个普通 JSON 运行记录，避免多文件一致性设计。定义明确的 artifact_type/format_version，至少包含：

- status、安全 error（阶段、类别、说明）、实际问题文本和 top-k。
- 文档产物摘要、E1 build_id、非敏感编码契约。
- HTTP 尝试数、请求状态/ID、有效用量和完整性、耗时。
- 已验证的问题向量（若成功编码），以及 E2b 的结构化检索结果（若检索成功）。不复制全量文档向量。

前置失败：0 次请求，用量已知合计 0、complete=true 表示没有请求。请求后无有效 usage：已知合计可为 0，但 complete=false，不能据此推断未计费。编码成功但后续检索失败：保留已验证问题向量、已知用量与失败阶段，不伪造成功候选。仅返回向量合法但用量未知时，检索可成功而用量仍不完整。

失败即停止后续步骤并尽量保存运行记录；正常异常路径退出非零。完整结果在运行结束写入预留文件；磁盘失败/强制终止可能留下空/部分文件，需明确限制及安全提示，不自动付费重跑。保存成功与流程成功分别判断，不因文件存在就认定成功。不要宣称事务保存、断点恢复或并发锁。

CLI 展示问题、状态、请求数和用量，以及候选排名、分数、原文和来源；不把完整向量刷到终端。调用函数返回结构化结果，展示由 CLI 负责。

## 四、离线测试先行

使用临时 E1/E2b 产物、假配置及模拟传输，测试不依赖个人 test-output 或真实密钥。当前完整回归基线为 119 项。

重点覆盖：

- 资料过期、产物损坏、来源/构建不匹配、配置错误和编码不兼容：均零 API 调用。单独断言请求函数未被调用。
- 空问题、过长输入、非法 top-k、输出存在或无法预留：零 API 调用，旧文件不变。
- 正常流程只发送一次 query 请求，输入文本与实际问题一致；文档编码/build/prepare 不被调用。
- HTTP 错误、超时、非法响应/索引/向量：最多一次尝试、无重试；安全失败结果可保存。
- 响应向量无效但 usage 有效，以及编码成功但 usage 缺失，两种情况区分准确。
- 请求成功后资料被修改，E2b 复查拒绝检索，保留已知用量与已验证问题向量，不返回陈旧结果。
- 成功结果与 E2b 既有 search 一致，保留真实问题、来源和候选提示；写入失败安全退出，不泄露模拟密钥。

运行完整离线回归。没有真实验证授权时，到此更新交接并停止；不要借实现授权执行真实 API 验证。

## 五、真实验证提案：待用户确认

以下仅为提案，不是调用授权。本轮主会话和任务书生成过程不调用 API。

建议确认后只验证两个新问题，各独立运行一次、各编码一个问题、top-k=3：

1. 相关问题：“发现迁移部分执行或执行状态无法确认时，可以直接重跑原脚本吗？”人工预期迁移手册相关章节能说明限制，观察 top-3 原文是否相关及适用范围，不生成回答。
2. 范围外问题：“公司差旅报销的住宿标准是多少？”资料中没有此业务主题。观察即便返回候选也不能宣称有答案；不要求模型分数低于任意阈值。

预算：合计最多 2 次 HTTP 尝试（含失败），每次一条问题，零文档编码、零生成调用、零重试。真实提案另将每条输入限制为最多 256 UTF-8 字节，输出维度沿用现有产物 1024；这不是精确 tokens 预算。第一个运行的请求、响应或保存出现失败时，停止整个真实验证，不继续第二个、不自动补跑。新的人工重跑需另行确认。

调用前从官方资料核实当前地域、接口限制、费率和账户可用性；不可凭历史用户报告余额推断当前余额。不为核实可用性额外发模型探测请求，不要求读取账单或账户余额；用户确认服务可用，或标注余额未查。依据实际返回 tokens 估算费用并注明不是账单；无法确认必要信息时先报告。

使用新的 test-output/rag/e2c/ 路径保存两个独立结果；报告各自及合计 HTTP 尝试、tokens/未知用量、维度、原文命中观察。最多两条观察不等于系统性检索效果评估。
