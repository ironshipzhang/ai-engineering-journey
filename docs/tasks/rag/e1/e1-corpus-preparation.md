## 最小交付

### 1. 三份资料

在 toy-agent/knowledge/ 准备《发布规范》《数据库迁移手册》《发布后检查清单》，中文为主，每份约 600–1000 汉字，每份只保留一个有效版本。小型 JSON 目录明确 document_id、title、version 和相对路径。原文与目录纳入版本控制，不使用真实业务资料。

- 有答案：迁移失败后重跑前检查什么？手册明确包含执行日志、迁移版本记录、是否部分执行。
- 证据不足：紧急发布能否跳过迁移验证，由谁批准？可以提供常规验证条款，但不提供足以确认紧急豁免与审批人的依据。

### 2. 切块与来源

复用所选组件，优先保持标题、段落和关键条件关系，明确大小与重叠的单位及参数。不要为追求零依赖自行实现通用切分器，不进行检索调参。

片段至少保留 chunk_id、document_id、文档标题/版本、相对来源路径、章节及文本。提供可以核对原文的定位方式；库若转换或重组文本，应区分处理后文本和原文依据，不能伪造精确行号或偏移。重复标题、重复片段应有可区分标识。相同输入与处理规则产生确定性片段，不要求编辑后所有 ID 保持不变。

### 3. 构建清单

记录产物类型/格式版本、文档清单及版本、SHA-256 内容指纹、切块规则和组件版本/实际参数、片段数量及产物完整性信息。标明这是 prepared corpus，不是向量索引。时间信息不参与确定性标识；不填假 embedding 模型、假向量或未经选择的编码配置。

### 4. 全量准备与变化检查

提供两个简单命令或子命令，名称由子会话确定并写清运行方式：

- prepare：读取并校验全部当前资料，生成片段和构建清单。默认拒绝覆盖已有构建目录，使用新输出目录；先临时准备并校验，再发布完整目录，失败不能成为可用构建。只纳入当前文档集合，删除的文档不残留。结束前再次核对输入；构建中变化则失败，不自动循环重试。
- check：比较当前资料、目录和处理配置与构建记录。匹配报告成功；新增/修改/删除或配置变化报告需重建、非零退出；不可读、损坏或缺少产物报告失败、非零退出。不得将检查失败当成资料没变化。校验片段文件完整性，不只比较原文哈希。

输出与原文分离，运行产物写入已忽略目录或为专用产物目录设置忽略规则；原文、目录、代码和必要测试继续版本控制。不引入活动索引指针、增量更新、文件监听、后台队列或通用锁服务。

每次问答前检查及过期拒绝在 E2 集成时验证；E1 只实现资料准备与独立检查，不能据此宣称完整索引生命周期已实现。

## 验证与范围

只运行离线测试和本地命令，不读取真实密钥、不调用生成/embedding API，不下载模型。允许浏览公开官方资料并安装本任务所需普通库。

验证实际项目行为：资料/元数据加载；片段确定性与原文可追溯；关键条件不丢失；新增/修改/删除和处理配置变化；缺失/不可读/损坏数据；构建中变化；已有输出不覆盖；失败不发布可用目录；新构建删除旧片段。测试不要求遍历第三方库内部实现，不写大量镜像断言。完整运行已有测试，确保 D/D2 不受影响。

不修改现有 Agent 协议、配置、共享摘要提示词、历史评估或失败策略；不实现 embedding、检索、生成回答、RAG tool 或 MCP。
