## 目标和边界

E2a 证明远程编码接口可用，其 JSON 是验证记录。E2b 从已有成功记录导入完整文档向量，结合经过 E1 check 的片段生成独立检索产物。查询时接收已有问题向量，计算余弦相似度，返回 top-k 原文和来源。

Toy 全程只使用 JSON，不引入 PostgreSQL、pgvector、向量数据库服务、ANN 索引或高层 RAG 框架。当前只有 15 个片段，逐个计算精确余弦相似度即可；如评估新增依赖，应遵循 AGENTS.md 的选库原则，不为小规模计算引入整套框架。

本轮不读取真实密钥、不调用任何模型 API、不重新编码文档。任意新问题的在线编码、生成回答、E3 工具集成留到后续任务，不顺手实现。

## 一、构建独立 JSON 向量产物

已有本地输入：

- E1 正常 prepared corpus：test-output/rag/e1/20261028/build-001
- E2a 成功记录：test-output/rag/e2a/e2a-20261029-001.json

若这些本地产物缺失、过期或不匹配，报告原因，不联网补采。不要使用 corrupt-copy。

构建前执行 E1 check，复用原有行为，不自动 prepare。只接受格式正确、status=succeeded、全量覆盖当前 corpus 的 E2a 记录；拒绝失败/部分结果、limited_sample、缺失/重复/额外 chunk_id、build_id 不匹配、错误来源映射、非法维度/向量。不能只信任记录中的成功标记、数量或 norm；重新校验。已知用量缺失本身不意味着向量无效，用量与向量可用性继续分开。

最小产物应包含：

- artifact_type、format_version、E1 build_id。
- 明确的非敏感编码契约：provider、model、dimension、接口、document/query 文本类型、prefix/instruct、原文处理与归一化方式等实际影响向量空间或输入的字段。
- 每个文档向量与 chunk_id 的唯一对应，以及 E1 的原文、document_id、标题/章节和来源定位；原文及来源从校验通过的 E1 获取，不依赖 E2a 中不存在的文本字段。
- 完整性校验信息。采用简单、确定的 JSON 序列化与内容摘要即可，说明摘要覆盖范围，不把校验和说成防恶意篡改签名。

构建输出使用新的 test-output/ 路径，拒绝覆盖；已有文件不受失败影响。产物损坏或保存中断时，后续读取必须拒绝，不把文件存在视为成功。不要求数据库事务、fsync 崩溃恢复、断点续建、增量更新或跨进程文件锁。

编码兼容契约与运行元数据分开：密钥、超时、批量大小和历史用量不应作为向量空间标识。endpoint/业务空间等保留可追溯信息，说明是否纳入当前保守兼容策略。不比较整份 public() 字典来代替语义判断。不实现供应商间兼容性猜测；模型名相同也不能检测供应商内部未声明的模型更新，记录此限制。

## 二、独立检索

提供可被其他函数调用的检索接口，并有小型 CLI。CLI 参数命名自行保持项目风格，文档给出实际可运行命令。

- 输入为已加载且验证过的 JSON 向量产物、问题向量及其编码元数据、top-k；本轮 CLI 可从 E2a 成功记录导入 query。
- 入口先检查当前 E1 资料和检索产物一致、产物完整、编码契约兼容，再检索。资料变化、索引损坏、编码不兼容均明确失败，不自动重建或继续使用旧数据。检查仅保证本地读取快照，不承诺网络过程或并发修改锁定。
- 问题与文档向量维度必须匹配，拒绝 bool、非数值、NaN/Inf 和零范数。按公式计算余弦，不假设供应商已归一化；复用或抽取适当校验能力，避免复制两套规则。
- 返回按分数降序排列的 top-k；同分使用明确且稳定的规则，例如 chunk_id 升序。top-k 必须是正整数，超过片段数返回全部，并明确实际数量。
- 返回结构化结果：问题、排名、余弦分数、chunk_id、原文、来源和必要的构建/编码信息。CLI 展示与函数返回分离；如保存结果，拒绝覆盖。
- 不把相似度解释为答案正确率。此次不拍脑袋设“有答案”阈值：无关问题也可能返回最相近片段，结果必须标明只是候选证据，不自动宣称证据足够。

不要把 E2a 的固定问题向量包装成可检索任意新文本：使用已有 query 时展示并核对其真实文本，不允许用另一个问题标签冒充已编码的问题。

## 三、验证与验收

新增离线测试围绕项目契约，不测试第三方库全部内部实现：

- 成功导入全量结果；拒绝失败/部分记录、重复/缺失/额外 ID、来源或 build_id 不一致。
- 产物内容与校验和不一致、原文变化、模型/维度/输入处理不兼容时拒绝检索。
- 手工可算的小向量验证余弦、排序、负分、同分稳定性及 top-k 边界；拒绝非法向量。
- 来源和原文能逐条对应 E1；输出已有文件时拒绝覆盖。
- 所有路径均无 API 调用，不需要真实配置。复用假密钥或模拟响应；新增测试不依赖 test-output/ 中的个人本地产物。

运行完整离线回归（当前基线 103 项），并用现有真实结果完成一次零 API 的端到端演示：导入 15 个文档向量，使用既有问题“数据库迁移失败后，重跑前需要检查什么？”的向量，展示 top-3 原文与来源。保存新结果到忽略目录，人工对照原文解释排序是否合理。

该演示只能说明一个既有问题的检索观察；手工向量测试只能验证算法与机制。不要将二者写成多问题语义评估通过，不新造真实模型结果。
