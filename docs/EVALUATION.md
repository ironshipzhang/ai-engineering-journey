# 小型项目摘要事实评估

> 阶段状态：学习练习已结束。以下保留历史标准、输出和评审过程，不作为当前改词或追分待办。后续端到端评估随新机制另行安排。

## 范围与数据

本轮只测“给定项目状态 → 结构化摘要”，不重复评估工具选择或 Loop 控制。使用已有 SUMMARY_PROMPT、deepseek-flash、非思考模式、JSON 输出、400 输出 tokens 与 30 秒网络操作超时，每条样例一次请求，无自动重试、无额外评判模型或依赖。

评估集：[project_summary_cases.json](../toy-agent/evals/cases/project_summary_cases.json)，6 条虚构状态，覆盖未解除阻塞、多个阻塞、明确无阻塞、信息不足、阻塞已解除和条件计划。每条样例包含 status、按摘要字段列出的 required_facts，以及 unsupported_claims。后两项仅用于本地评审，不发送给生成模型。

真实基线：[baseline_20261010.json](../toy-agent/evals/results/baseline_20261010.json)，保存当时的提示词、模型、原始样例、有效摘要、结束原因和用量。不含密钥；factual_review=pending 表示采集脚本没有自动给事实结论，本页记录 Codex 对保存结果逐条对照的初评及文档收尾复核，尚未经用户逐条确认。

## 评审标准

1. 格式：必须通过已有 parse_summary；截断、异常结束、工具调用或非法结构视为生成失败，不能算事实通过。
2. 阻塞遗漏：每个仍有效的阻塞与明确风险都应出现在 blockers；已解除的阻塞不得当作当前阻塞。
3. 事实保留与字段：required_facts 是语义检查点，不要求逐字匹配；关键事实需出现在对应字段。把下一步计划只写进 blockers 记为字段归属问题；完全不提条件计划记为遗漏。
4. 无依据的信息：摘要每项须可由原文支持，不得增加负责人、时间、完成状态或确定性承诺；尤其不能把“计划、如果、可能”升级为事实。
5. 信息不足：依现有提示词，无对应信息可用 []；这只能表示未提取出阻塞，不能证明项目无阻塞。explicit_no_blockers 与 missing_information 都可能输出 []，当前摘要结构无法区分这两种知识状态。

不使用关键词命中率或唯一参考答案作为事实正确率：同义表达可能正确，带否定或已解决状态的关键词命中也可能错误。每次结果应逐条对照，而不是因为 JSON 合法就宣称事实正确。

### 下游用途与判定方法

已确定用途：人工阅读整个项目摘要；程序单独读取 blockers，筛选需要关注的项目；人工可能单独读取 next_steps，了解行动及计划。摘要暂不自动决定发布或执行操作。blockers=[] 只表示本次未提取到阻塞或风险，不能证明项目确定无风险。

V2 将内容验收拆成三个维度，分别标注“通过”“有问题”“待讨论”，不合成单一总通过率。结构有效仍是评审前提；本次使用已有有效输出，不生成新结果。若一个维度既有确定问题又有歧义，标“有问题”并补充歧义；“待讨论”用于原文或关联确有歧义，说明原因，不强行判定。

1. **事实保留**：先看整个摘要是否保留关键进展、阻塞、明确风险、行动、计划及其前提、时间和不确定性；完成、进行中、解除等状态须准确，不增加无依据的信息或将计划升级为承诺。事实在错误字段中不等于事实完全遗漏。信息未提供不要求补全，也不能断言其不存在。
2. **字段归属**：progress 包含完成及进行中的进展；当前阻塞与原文明示的风险必须进入 blockers，已解除阻塞不能当作当前阻塞。行动及明确计划必须进入 next_steps，计划的前提、时间及不确定性应随计划进入该字段，使其可单独阅读；对应明确风险同时进入 blockers，允许有依据的跨字段重复。普通条件计划和单纯信息缺失不自动成为风险。原文确有歧义则待讨论。
3. **表达关联**：排查行动与原因状态应能清楚关联到对应阻塞；同项只是实现关联的一种方式，不强制同一数组元素。检查孤立、含糊或易误读的描述，重复仅在影响理解时算问题，不一律禁止。

这是新增的业务验收视角，旧标准、旧结论、required_facts、unsupported_claims 及原始输出均保留。旧规则中“附在对应阻塞”的要求在 V2 按关联是否清楚解释，不改写规则文件。V2 的判定不是重写历史评分，也不自动接受当前候选。
